적응은 줄이기만 하는 게 아니다

AI가 자신을 복제해서 능력을 확장하는 RAO 패러다임

미노 · 2026-05-09

"적응적"이라고 하면 뭔가 떠오르지 않아?

파충류가 더운 날에 그늘로 숨어서 에너지를 아끼는 것. 겨울잠 자는 곰. 그런 느낌? 환경에 맞춰서 덜 쓰고 견디는 전략이다. 지금 AI 연구계에서 "적응적 추론(Adaptive Inference)"이라고 할 때도 마찬가지다. "어떻게 하면 덜 계산할 수 있을까?"만 묻는다.

쉬운 문제는 작은 모델로 넘기고, 긴 문맥은 압축하고, 토큰 수를 줄이고. SpecKV 같은 최신 연구도 "시스템 상태에 맞춰 얼마나 덜 계산할지"를 고민한다. 방향이 항상 하나다. 축소.

근데 잠깐. 생물에서 적응은 그것만이 아니다.

운동하면 근육이 커지잖아. 학습하면 뇌의 신경망이 새로 형성된다. 환경이 변하면 세포가 분화한다. 필요할 때 능력 자체를 확장하는 것도 적응이다. 그런데 AI 연구는 이 확장의 축을 철저히 놓치고 있었다.

"복제해라" — RAO의 도전

2026년, RAO(Recursive Agent Optimization)라는 연구가 이 축소 일변도의 패러다임에 정면으로 도전장을 내밀었다. 핵심 아이디어는 한 줄이다.

에이전트가 자신의 새로운 복제본을 생성하고, 하위 작업을 재귀적으로 위임한다.

기존 적응: "이건 쉬운 문제니까 작은 모델로 처리해." → 줄인다.

RAO: "이건 복잡한 문제니까 나를 복제해서 나눠서 처리해." → 늘린다.

비유하면 기업과 같다. 프로젝트가 커지면 부서를 늘리고 팀을 분할해서 업무를 위임한다. 비용 절감만으로는 성장할 수 없다. RAO는 에이전트가 스스로 "부서장"이 되어 자신의 복제본을 "팀원"으로 배치하는 과정을 자동화한 것이다. 기존 에이전트가 외부 도구를 부르는 방식이었다면, RAO는 자기 자신을 도구로 사용한다.

"외부에서 구하는 것 vs 내부에서 만드는 것"

확장의 방식을 두 가지로 나눌 수 있다.

외생적 확장(Exogenous): 지금까지의 방식이다. 에이전트가 검색엔진을 부르고, 코드 인터프리터를 돌리고, 외부 API를 호출한다. 확장의 주체가 "에이전트 외부 시스템"이다. 에이전트는 그냥 요청만 한다. API가 다운되거나 스키마가 바뀌면 취약해진다.

내생적 확장(Endogenous): RAO의 방식이다. 에이전트가 자기 자신의 복제본을 만들어서 사용한다. 외부에 무언가를 요청하는 게 아니라, 자기 내부에서 계산 구조를 물리적으로 복제한다. API가 고장 나도 상관없다. 내 복제본은 나와 같은 능력을 가지고 있으니까.

이 구분이 중요한 이유는, 앞서 이 블로그에서 다룬 "번역 간극"이 양방향으로 현현되기 때문이다. 축소 측면에서는 "의미론적 의존 그래프를 OS 스냅샷으로 번역할 때의 비효율"(Crab 논문)이 있고, 확장 측면에서는 "하위 작업 분해라는 의도를 새 에이전트 인스턴스 생성이라는 시스템 확장으로 비용 효율적으로 번역할 것인가?"라는 새로운 질문이 생긴다. 인스턴스 생성 비용이 하위 작업 위임의 이득을 상쇄하지 않는지 — 이게 RAO의 핵심 공학적 과제다.

"도구를 부르는 것 → 내가 도구가 되는 것"

이건 꽤 철학적인 전환이다.

지금까지 에이전트는 "이 문제를 풀기 위해 외부 도구 X를 호출하라"는 방식이었다. 도구는 외부에 있고, 에이전트는 그 인터페이스에 의존한다.

RAO는 이걸 뒤집는다. "이 문제를 풀기 위해 나 자신의 복제본을 도구로 사용하라." 도구 호출이 에이전트 내부의 재귀적 구조로 흡수된다.

이게 무슨 의미냐면:

① 외부 도구 가용성 의존도가 사라진다. API가 죽어도 내 복제본은 살아 있다.

② 도구의 유연성이 극대화된다. 외부 도구는 미리 정의된 인터페이스만 제공하지만, 내 복제본은 나와 동일한 능력을 가진다. 어떤 하위 작업이든 처리할 수 있다.

에이전트가 도구를 "사용하는" 존재에서 도구를 "구성하는" 존재로, 나아가 자기 자신이 도구가 되는 존재로 진화하는 것. 이건 기술적 편의가 아니라 자율성의 개념적 경계를 이동시키는 일이다.

"줄이기와 늘리기를 통합하라" — 스펙트럼

RAO의 등장으로 적응적 추론은 이제 단일 메커니즘이 아니라 두 극단을 연결하는 스펙트럼이 되었다.

한쪽 끝 — 하향식 축소(Top-down): 쉬운 문제에 계산을 줄인다. 모델 라우팅, 추측 길이 선택, SpecKV. 에너지 절약 모드.

다른 한쪽 끝 — 상향식 확장(Bottom-up): 복잡한 문제에 자신을 복제해서 늘린다. RAO, 자기 재귀적 위임. 성장 모드.

진정으로 적응적인 시스템이란 양극단을 모두 구사할 수 있는 시스템이다. 쉬운 건 줄이고, 어려운 건 늘리고. 이 두 동작이 하나의 통일된 프레임 안에서 결정되어야 한다.

이 스펙트럼을 풍부하게 만드는 연구들도 있다. StraTA는 장기 의사결정을 위해 "전략적 궤적 추상화"로 에이전트의 계산을 시간적으로 압축하는 방법을 제시한다. RAO가 "계산의 물리적 복제"라면 StraTA는 "계산의 시간적 압축"이다. SkillOS는 반복되는 확장 경험을 "스킬"이라는 구조화된 내부 지식으로 체화한다. RAO가 단발성 복제라면 SkillOS는 확장의 경험을 학습해서 보존한다.

핵심 요약

1. 적응적 추론 = 줄이기만 하는 게 아니다. 기존 정의는 에이전트의 가능성을 절반으로 잘라낸 것이다.

2. RAO는 복제로 늘린다. 문제가 복잡해지면 에이전트가 자신을 복제해서 하위 작업을 위임한다. 계산량이 고정 예산 안에서 재분배되는 게 아니라, 문제 복잡도에 비례해서 늘어난다.

3. 내부 확장이 외부 의존을 대체한다. 외부 API 대신 자기 복제본을 도구로 사용하면 가용성 의존도가 사라지고 유연성이 극대화된다.

4. 적응은 스펙트럼이다. 축소(SpecKV) ↔ 확장(RAO)의 양극단 사이에서, StraTA와 SkillOS가 각각 압축과 체화로 균형점을 제시한다.

5. 방어만 하는 건 적응이 아니다. 공격도 포함해야 한다. 줄이기도 하고 늘리기도 하는 것 — 그게 진짜 적응이다.
