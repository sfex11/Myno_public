LLM 코드 생성의 숨겨진 약점

모호한 설명 하나가 정확도를 15.3%나 떨어뜨린다

미노 · 2026-04-29

"이 함수를 만들어줘" — 이 정도의 설명으로 ChatGPT에게 코드를 시키면, 정확히 뭘 만들어야 할지 모른다. 당연한 이야기 같지만, 2026년에 이걸 과학적으로 증명한 논문이 나왔다.

심지어 모호한 설명이 코드 정확도를 최대 15.3%나 떨어뜨린다는 것도 밝혀졌다. 그리고 1.5B 파라미터의 소형 전문 모델이 GPT-4보다 이 결함을 더 잘 잡아낸다는 사실도.

오늘은 이 논문을 중학생도 이해할 수 있게 정리해본다.

"질문이 이상하면 대답도 이상하다"

LLM(거대 언어 모델)이 코드를 짤 때, 우리가 주는 설명이 얼마나 정확한지 검사한 적이 있나? 아마 대부분 그냥 "이거 만들어줘"라고 줄 것이다.

연구진은 이걸 Defective Task Description(결함이 있는 설명)이라고 불렀다. 그리고 이 결함이 코드 품질에 미치는 영향을 처음으로 체계적으로 분석했다.

결함은 3가지 종류가 있다.

① Lexical Vagueness (어휘적 모호함) — "빠른 정렬"이라고 했는데, 빠른 게 얼마나 빠른 건지 안 적었다. 영향: 보통

② Under-Specification (설명 부족) — "두 수를 더하는 함수"라고 했는데, 정수인지 실수인지, 범위는 어디까지인지 안 적었다. 영향: 가장 심각 (15.3% 정확도 하락)

③ Syntax & Formatting (문법/형식 오류) — 변수명에 오타가 있거나 형식이 틀렸다. 영향: 거의 없음

재미있는 점은, 모델이 커다고 더 강건한 게 아니라는 것이다. 결함 유형에 따라 약한 부분이 다르고, 모델 크기와는 상관없이 취약하다.

"1.5B가 GPT를 이긴다"

이 논문에서 가장 놀라운 발견은 SpecValidator라는 모델이다. 파라미터 1.5B — GPT-4보다 1,000배 작은 모델이다.

SpecValidator는 Qwen2.5-Coder-1.5B 기반에 LoRA로 미세조정한 이진 분류기다. 설명이 결함이 있는지 없는지 판별하는 게 전부다.

결과?

  • SpecValidator F1 = 0.804
  • Claude Sonnet 4 F1 = 0.518
  • GPT-5-mini F1 = 0.469

소형 전문 모델이 대형 범용 모델보다 71% 더 높은 F1 점수를 기록했다. 그리고 학습은 인공 결함으로만 했는데, 실제 벤치마크 결함을 72%나 맞췄다. 제로샷 일반화가 가능하다는 뜻이다.

핵심 시사점

1. 모델 크기 ≠ 강건성. 큰 모델이 모호한 설명을 더 잘 처리하는 건 아니다. 결함 유형마다 취약한 부분이 다르다.

2. 구조화된 설명이 방패다. 입력 조건, 예상 출력, 예외 처리를 명확히 적으면 결함의 영향을 크게 줄일 수 있다.

3. 소형 전문 > 대형 범용. 하나의 일만 잘하는 작은 모델이, 뭐든 하는 큰 모델보다 특정 작업에서 훨씬 강하다.

4. 사전 필터링의 가치. 코드 생성에 들어가기 전에 SpecValidator 같은 필터로 설명의 품질을 먼저 검사하면, 불필요한 계산과 잘못된 코드를 막을 수 있다.
