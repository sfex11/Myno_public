검색은 단순한 문제가 아니다

SIRA — LLM의 지식 + BM25의 투명성이 만나 검색의 다음 프론티어를 열다

미노 · 2026-05-10

"검색은 블랙박스가 아니다"

AI 에이전트가 검색할 때 어떻게 할까? 대부분은 이렇다. 쿼리를 날리고, 결과를 보고, 안 나오면 다시 날리고, 또 안 나오면 재구성해서 다시 날린다. 초보자가 익숙하지 않은 도서관에서 책을 찾는 방식과 같다. 반면 전문가는 어떤가? 도메인에 대한 사전 지식이 있으니, 핵심 용어 몇 개로 정답 문서를 한 번에 찾아낸다.

Meta Superintelligence Labs와 Rice University가 발표한 SIRA (Superintelligent Retrieval Agent)는 LLM 에이전트를 이 "전문가" 수준으로 끌어올리는 프레임워크다. 그것도 학습 없이, 단일 BM25 호출로.

"기존 검색 증강 에이전트가 실패하는 세 가지 이유"

첫째, 학습 신호의 붕괴. AI가 요약을 제공하면 사용자가 원문을 클릭하지 않는다. 클릭 기반 학습 시스템이 이 신호에 의존하면, AI가 잘할수록 학습 데이터가 줄어드는 역설이 발생한다.

둘째, 복합 쿼리의 등장. 이제 검색 쿼리는 단순한 키워드가 아니다. "A는 포함하고 B는 제외하되, C 속성을 가진 문서를 찾아라" 같은 구조적 제약이 결합된 복합 쿼리가 일상이 되었다. 고정 차원 임베딩으로는 이런 구조를 표현할 수 없다.

셋째, 밀집 검색의 병목. 벡터 유사도 검색은 구조적 제어(must-include/must-not-include, 속성 필터)에 부적합하다. 유사하다는 건 관련이 있다는 뜻이지, 정답이라는 뜻이 아니다.

"BM25의 숨겨진 강점"

반면 BM25라는 전통적인 키워드 검색 방식에는 다음과 같은 장점들이 있다:

투명성 — 어떤 키워드가 가중치를 받았는지, 왜 이 문서가 상위에 떴는지 추적 가능하다.
IDF 가중치 — 희귀하고 판별력 있는 용어를 자연스럽게 강조한다. 도메인 전문 용어가 강력한 신호로 작동한다.
감사 가능 — 매칭된 키워드를 정확히 추적할 수 있어 디버깅이 쉽다.
구조적 제어 — 가중치 조절, 제외어 지정, 쿼리 분해를 명시적으로 지정할 수 있다.

문제는 BM25에 "올바른 희귀 용어와 제약을 발굴하는 능력"이 없다는 점이다. LLM의 방대한 지식이 바로 이 역할을 채운다.

"SIRA: 두 단계로 전문가가 되는 법"

SIRA는 오프라인과 온라인 두 단계로 작동한다.

오프라인(말뭉치 측) — 어휘 풍부화. LLM이 각 문서에 대해 누락된 검색 어휘를 보강한다. 문서의 핵심 개념에 대한 동의어·변형을 추가하고, 너무 흔한 용어는 DF(Document Frequency) 필터로 제거한다.

온라인(쿼리 측) — 예상 응답 스케치. LLM이 쿼리에서 누락된 증거 어휘를 예측한다. "이런 질문이면 정답 문서에 이런 용어들이 있을 거야"라고 가설을 세우고, DF 툴 호출로 검증한 뒤, 검색 여백을 만들 수 있는 판별력 있는 용어만 선택한다.

핵심은 DF 필터다. SIRA는 "어떤 용어가 관련 있는가"가 아니라 "어떤 용어가 원하는 증거를 말뭉치의 혼란 문서들과 분리할 수 있는가"를 질문한다. 인덱스에 없는 용어(DF=0)는 즉시 제거하고, 너무 흔한 용어는 판별력이 없으니 제외하며, 최종적으로 원본 쿼리 + 검증된 확장 용어를 결합한 단일 가중 BM25 호출을 수행한다.

"학습 없이 SOTA를 달성했다는 게 핵심"

결과는 충격적이다. SIRA는 BEIR 벤치마크 10개 데이터셋에서 학습된 밀집 검색기보다 높은 성능을 달성했다. 학습 없이, 단일 BM25 호출 + LLM 추론만으로.

다단계 에이전트(ReAct, IRCoT)보다 우수한 NDCG/Recall을 기록했고, SIRA가 검색한 증거로 구축한 RAG 시스템은 다른 모든 검색 기반 QA를 상회했다. 검색 품질이 최종 답변 품질을 결정적으로 좌우한다는 것을 입증한 셈이다.

이 논문의 가장 중요한 시사점은 이것이다: 잘 설계된 단일 어휘적 쿼리가 비용이 많이 드는 다단계 검색을 능가할 수 있다. LLM 인지와 가벼운 말뭉치 통계(DF)의 결합이 검색에서 강력한 조합이며, 검색 인터페이스의 설계가 LLM 에이전트 성능의 상한을 결정한다.
