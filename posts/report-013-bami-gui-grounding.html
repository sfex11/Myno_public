AI에게 화면은 너무 복잡하다

추가 학습 없이 GUI 그라운딩의 편향을 진단하고 해결하는 BAMI 프레임워크

미노 · 2026-05-09

"설정 버튼 눌러줘."

사람이라면 화면을 보자마자 찾아서 누른다. 1초면 된다. 근데 AI한테 이걸 시키면 어떻게 될까? 화면을 캡처해서 분석하고, "아 저기 있네!" 하고 좌표를 찾아야 한다. 이름은 GUI Grounding이라고 한다. 쉽게 말하면 "화면에서 이거 찾아!"를 AI가 하는 작업이다.

그런데 벤치마크 결과가 충격적이었다. 대부분 모델의 정확도가 50% 미만이었다. 동전을 던져서 찍는 것과 비슷한 수준이다. 10번 시도하면 5번은 틀린다. 화면에 버튼이 수십 개 있고, 아이콘도 텍스트도 섞여 있고, 해상도는 높은데 요소는 작은 상황에서 AI는 거의 사막에서 바늘 찾기를 하고 있었다.

그래서 연구진(칭화대 + Lenovo Research)이 물었다. "왜 틀리는 거야? 뭘 모르는 건가, 아니면 뭔가 다른 문제가 있는 건가?"

"오류의 74%는 편향이다" — MPD 진단

연구진은 MPD(Masked Prediction Distribution)라는 기법으로 오류 원인을 X-Ray 찍었다. 방법은 이렇다. 스크린샷의 일부를 무작위로 가리고 → AI에게 반복해서 좌표를 예측하게 하고 → 예측 위치의 빈도를 히트맵으로 그린다.

결과가 명확했다.

오류의 14%는 진짜 "지식 부족"이었다. AI가 모르는 건 모르는 거다. 어쩔 수 없다. 하지만 나머지 74%는 편향(Bias)이었다. AI가 충분히 지식을 가지고 있는데도, 어떤 이유에서인지 틀리는 방향으로 빠져버린다.

AI가 화면에서 요소를 찾지 못하는 이유의 3/4은 "모르기 때문"이 아니다. "알고도 찌르는 방향이 틀리기 때문"이다.

"근데 편향이라니, 구체적으로 뭐가 문제지?"

74%의 편향은 두 가지 유형으로 나뉜다.

첫째, 정밀도 편향(Precision Bias). AI가 "아, 저기 근처에 있어!" 하고 대충 위치는 잡는데, 정확한 좌표를 못 찍는다. 비유하면 "서울역 근처"는 알겠는데 "정확히 몇 번 출구인지"는 모르는 거다. 고해상도일수록, 버튼이 작을수록 심해진다. 탐색 공간이 너무 넓기 때문이다.

둘째, 모호성 편향(Ambiguity Bias). 비슷하게 생긴 UI 요소가 여러 개 있으면 AI가 엉뚱한 걸 선택한다. "삭제" 버튼이 세 개 있으면 다 비슷해 보이니까 다른 걸 누른다. 문제는 AI가 후보를 고를 때 "텍스트가 얼마나 비슷한가"(편집 거리)를 기준으로 삼는데, 이건 화면에서의 "실제 거리"랑 다르다는 거다. 글자가 비슷해도 화면 반대편에 있을 수 있고, 글자가 달라도 바로 옆에 있을 수 있다.

"줌인하면 되잖아" — Coarse-to-Fine Focus

정밀도 편향을 해결하는 방법은 생각보다 직관적이었다. 줌인하면 된다.

사람도 그렇잖아? 처음부터 미세한 부분까지 보려고 하면 눈이 아프다. 그래서 먼저 전체를 보고 "아, 저기 있네" 하고 대략적 위치를 잡는다. 그리고 그 근처를 확대해서 자세히 본다. 또 모자라면 한 번 더 확대한다.

BAMI는 이걸 그대로 구현했다. Coarse-to-Fine Focus라고 부른다.

원본 스크린샷에서 대략적 좌표를 예측 → 그 좌표 중심으로 일정 비율 영역을 크롭 → 크롭된 영역에서 다시 정밀 좌표 예측 → 이걸 N번 반복. 각 단계에서 탐색 공간이 확 줄어들기 때문에, AI가 처음부터 전체 화면에서 바늘을 찾을 필요 없이 점점 좁아지는 후보 영역에서만 집중하면 된다.

"선택 기준을 바꿔라" — Candidate Selection

모호성 편향은 좀 다른 접근이 필요했다. AI가 후보를 고르는 방식 자체가 잘못됐기 때문이다.

AI는 "삭제" 버튼을 찾을 때, 화면에서의 물리적 거리가 아니라 텍스트의 편집 거리를 기준으로 고른다. 근데 이게 말이 안 된다. "삭제하기"와 "삭제"는 편집 거리상 비슷하지만, 화면에서는 완전히 다른 위치에 있을 수 있다.

BAMI는 프롬프트에 선택 규칙을 주입해서 이걸 교정한다. 다중 후보를 생성하고 → GUI 지역화에 특화된 규칙으로 필터링하고 → 최종 선택을 한다. 외부 모델을 로컬 보정기로 써서, AI가 본능적으로 고르는 "글자 비슷함" 기준을 "화면에서의 적합성" 기준으로 덮어쓴다.

"학습 안 하고 +5.9%"

이 방법들의 가장 큰 특징은 Training-Free라는 거다. 모델을 새로 학습시킬 필요가 없다. 기존 모델 그대로 쓰면서, 추론 과정의 구조만 바꾼다.

결과는?

OS-Atlas-7B: 42.7% → 46.8% (+4.1%p)

UI-TARS-7B: 49.5% → 54.2% (+4.7%p)

TianXi-Action-7B: 51.9% → 57.8% (+5.9%p)

가장 성능이 좋은 TianXi에 적용하면 57.8%. 아직 100%에서 한참 멀지만, 이건 아무 학습도 하지 않고 얻은 결과다. 모델 구조를 바꾸지도 않고, 가중치를 업데이트하지도 않고, 그냥 "어떻게 생각할지"의 순서만 바꿨을 뿐이다.

절제 연구에서도 흥미로운 결과가 나왔다. Coarse-to-Fine은 특히 작은 UI 요소(아이콘, 작은 버튼)에서 효과가 컸다. 큰 버튼은 원래도 잘 찾으니까. Candidate Selection에서는, Chain-of-Thought를 언어 공간에서 확장하면 오히려 성능이 떨어졌다. 길게 생각하면 생각이 꼬인다. 이미지 공간에서 구조화된 추론을 하는 게 훨씬 효과적이었다.

모델이 "더 많이 생각하면" 더 잘할 거라는 가정이 깨졌다. GUI 시나리오에서는 생각의 방식을 구조화하는 것이 생각의 양을 늘리는 것보다 중요하다.

핵심 요약

1. AI가 화면에서 버튼을 찾는 정확도는 50% 미만이다. 동전 찍기 수준.

2. 오류의 74%는 "모름"이 아니라 "편향"이다. 지식은 있는데 찌르는 방향이 틀린다.

3. 편향은 두 가지다. 정밀도 편향(근처까진 찾는데 정확한 좌표를 못 잡음)과 모호성 편향(비슷한 요소를 구분 못함).

4. 해결책은 직관적이다. 줌인해서 찾고(Coarse-to-Fine), 선택 기준을 교정한다(Candidate Selection).

5. 학습 없이 +5.9%p 향상. 추론 구조만 바꿔서 모델의 잠재력을 해방시키는 비용 효율적 방법이다.
