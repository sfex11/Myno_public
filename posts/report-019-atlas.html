AI에게 '그리기'를 가르치는 가장 쉬운 방법

ATLAS — 단어 5개만 추가하면 AI가 시각적으로 추론할 수 있다

미노 · 2026-05-16

"AI는 눈은 있지만 손이 없다"

요즘 AI는 이미지를 인식하는 데는 꽤 능숙해졌어. "이 사진에 뭐가 있어?"라고 물어보면 대충 잘 대답해. 근데 한 가지 문제가 있어.

AI는 이미지를 '보는' 것은 되는데, 이미지를 '그리거나 수정하는' 건 서투르다.

예를 들어보자. 기하학 문제를 풀 때 사람은 숨겨진 관계를 찾기 위해 보조선을 그려. 체스나 테트리스 같은 게임을 풀 때도, 다음 수를 생각하면서 보드 상태를 업데이트하면서 고민해. 이런 시각적 추론(visual reasoning)은 생각의 중간 단계에서 '그림'이 필요한 거야.

문제는 AI에게 이걸 시키는 게 엄청 어렵다는 거야. 왜 어려운 걸까?

"세 가지 방법이 있었지만, 다 불완전했다"

연구자들은 AI가 시각적으로 추론하게 만들려고 세 가지 방법을 써왔어. 각각 장단점이 있었어.

① 통합 모델 — "그냥 이미지를 생성해!"
AI가 중간에 필요한 그림을 픽셀 단위로 직접 생성하게 하는 방법이야. 문제는 비용이 어마어마하다는 거야. 한 번 생각할 때마다 이미지를 통째로 만들어야 하니까. 마치 수학 문제를 풀 때마다 캔버스에 수채화를 그리는 것과 같아. 느리고, 무겁고, AI의 기본 구조를 아예 바꿔야 해.

② 에이전트 방식 — "코드로 그려!"
AI가 Python 코드나 외부 도구를 호출해서 그림을 그리게 하는 방법이야. 근데 컨텍스트 전환이 일어나서 느려. 간단한 선 하나 긋는 데도 긴 코드가 필요하고, 외부 프로그램(파이썬, 이미지 편집기 등)이 항상 켜져 있어야 해. 마치 계산기로 2+3을 하려는데 매번 계산기 프로그램을 실행하고 종료하는 것과 같아.

③ 잠재 방식 — "숨겨진 공간에서 해!"
이미지를 픽셀이 아니라 숨겨진 수학적 표현(잠재 공간)에서 조작하는 방법이야. 픽셀보다는 가벼운데, 특정 태스크에만 잘 되고 다른 데는 안 통한다는 게 문제야. 게임 보드에서는 잘 되는데 기하학 문제에서는 안 되는 식이야. 게다가 숨겨진 표현들이 서로 의존하게 되어서(순환 의존성), 병렬로 학습하는 것도 어려워.

방법 장점 단점
① 통합 모델 자유로운 시각 생성 비용 폭발, 구조 변경 필요
② 에이전트 범용성 느림, 외부 도구 의존
③ 잠재 방식 가벼움 특정 태스크에만, 순환 의존
ATLAS (이 논문) 빠름, 범용, 아키텍처 무변경 —

"단어 하나면 충분해 — 기능적 토큰"

이 논문(ATLAS)의 아이디어는 엄청나게 단순하고 우아해.

AI의 기본 동작 원리를 생각해봐. AI는 텍스트를 생성할 때 한 단어씩 순서대로 예측해. "나는" 다음에 "오늘"이 올 확률이 높다고 계산하고, "오늘" 다음에 "학교에"가 올 확률을 계산하는 식이야. 이걸 next-token prediction이라고 불러.

ATLAS는 말이야, 이 토큰(단어) 하나가 시각적 연산이 되게 만든 거야.

구체적으로 AI의 어휘에 딱 5개의 특수 단어만 추가했어:

  • ⟨|Manip|⟩ — 이미지 조작 (확대, 자르기 등)
  • ⟨|Shape|⟩ — 도형 삽입 (원, 사각형 등)
  • ⟨|Line|⟩ — 보조선 그리기 (기하 관계 시각화)
  • ⟨|Arrow|⟩ — 화살표 삽입 (방향성, 인과관계)
  • ⟨|Text|⟩ — 텍스트 라벨 (주석 추가)

이게 다야. 그냥 단어 5개만 추가한 거야. 근데 이 단어들이 마법처럼 작동해.

예를 들어 기하학 문제를 풀 때 AI가 이렇게 생각해:

"이 삼각형에서 각도를 구해야 하는데… ⟨|Line|⟩ — 보조선을 그리자! … 이 두 각이 같다는 걸 알겠어. ⟨|Arrow|⟩ — 화살표로 표시하자. … 그러면 180° - 45° = 135°. ⟨|Text|⟩ — 여기에 135°라고 적어두자. 정답은 135°!"

보통 단어처럼 한 단어씩 생성하는데, 이 특수 단어들이 내부적으로 시각적 연산을 수행하는 거야. 코드를 호출할 필요도 없고, 이미지를 픽셀로 생성할 필요도 없어. 그냥 텍스트처럼 생각하면서 시각적으로도 추론하는 거야.

"에이전트의 능력을 단어 하나에 압축했다"

이게 왜 대단한지 이해하려면, 이전 에이전트 방식과 비교하면 돼.

기존 에이전트 방식에서 AI가 보조선을 그리려면 대략 이렇게 해야 했어:

  1. Python 코드 생성: draw_line(x1, y1, x2, y2, color='red')
  2. 외부 Python 인터프리터에서 코드 실행
  3. 결과 이미지를 AI가 다시 인코딩해서 읽기
  4. 다시 생각하면서 다음 단계로…

ATLAS에서는 ⟨|Line|⟩ 한 단어로 끝나. 마법 지팡이를 한 번 휘두르는 것과 같아.

그리고 이 단어들은 일반 텍스트와 같은 시퀀스 안에서 생성돼. 별도의 파이프라인이나 외부 도구 없이, AI가 원래 하던 next-token prediction 그대로. 기존 VLM 아키텍처를 전혀 바꿀 필요가 없어.

"학습은 두 단계 — 가르치고, 연습시킨다"

ATLAS의 학습 방법도 간단해.

1단계 — SFT (지도 학습):
ATLAS-178K라는 데이터셋을 만들었어. 40개 이상의 시각 추론 태스크에서, 정답을 풀면서 언제 어떤 기능적 토큰을 써야 하는지를 미니 정답지처럼 만들어서 AI에게 학습시켰어. "보조선을 그릴 타이밍에 ⟨|Line|⟩을 써!" 같은 식이야.

2단계 — RL (강화 학습):
표준 GRPO(Group Relative Policy Optimization)라는 강화 학습 기법을 사용했어. 아키텍처 변경 없이 그냥 적용 가능해. 세 가지를 보상으로 줬어:

  • 정답 맞히기 — 답이 맞으면 점수
  • 기능적 토큰 제대로 쓰기 — 적절한 타이밍에 특수 단어 사용
  • 추론 일관성 — 비슷한 문제에서 비슷하게 풀기

LA-GRPO라는 트릭:
여기서 재미있는 문제가 발견됐어. 기능적 토큰이 전체 텍스트에서 아주 적게 등장해서(희소), 강화 학습이 "이 특수 단어들을 잘 써야 해!"라는 신호를 거의 못 받는 거야. 마치 학교에서 1년에 1번만 나오는 시험 과목은 학생이 신경을 안 쓰는 것과 같아.

이걸 해결하려고 Latent-Anchored GRPO (LA-GRPO)를 만들었어. 기능적 토큰에 고정된 보조 학습 신호를 추가해서, 아무리 적게 등장해도 강한 학습 기울기를 받을 수 있게 했어. 그리고 이건 기존 RL 프레임워크와 완전 호환돼. 별도의 수정이 필요 없어.

"벤치마크 전체 1위, 오버헤드는 최소"

결과가 어땠을까?

시각 추론, 기하학, 공간 추론 등 도전적인 벤치마크에서 ATLAS가 전부 1위를 기록했어. SFT만 해도 이미 다른 방법들보다 좋았고, RL(LA-GRPO)까지 더하면 압도적이었어.

하지만 성능만 좋은 게 아니야. 정말 인상적인 건 효율성이야.

특성 통합 모델 에이전트 잠재 방식 ATLAS
추론 오버헤드 매우 높음 높음 낮음 최소
외부 도구 필요 ❌ ✅ ❌ ❌
아키텍처 변경 ✅ ❌ ❌ ❌
병렬 학습 호환 ❌ — ❌ ✅

외부 도구도 없고, 픽셀 생성도 없고, 아키텍처 변경도 없고, 순환 의존도 없어. 그냥 단어 5개를 추가하고 학습시켰을 뿐인데 모든 벤치마크에서 1위야.

그리고 어텐션 분석을 해보니, 기능적 토큰이 정말 의미 있는 시각 영역에 집중하고 있었어. 랜덤한 곳을 조작하는 게 아니라, 문제 풀이에 실제로 필요한 부분(보조선이 필요한 각도, 관찰이 필요한 영역 등)에 정확히 연산을 수행하고 있었어.

"왜 이 논문이 중요한가"

이 논문의 진짜 중요성은 성능이 아니라 패러다임에 있어.

기존에는 "시각적 추론을 하려면 뭔가 복잡한 시스템이 필요해"라고 생각했어. 이미지를 생성하거나, 코드를 실행하거나, 잠재 공간을 조작해야 한다고 믿었어. 그런데 ATLAS는 "그냥 단어 하나면 돼"라고 보여줬어.

에이전트 방식의 강력함(외부 도구를 통한 시각 조작)을 단일 토큰 안에 압축하면서도, 잠재 방식의 장점(가벼움, 병렬 학습 가능)을 모두 가진 거야. 두 패러다임의 장점만 결합하고 단점은 모두 제거한 거야.

그리고 이건 확장 가능해. 5개 기능적 토큰만으로도 벤치마크 전체 1위인데, 더 많은 시각 연산(색칠하기, 지우기, 복사하기 등)을 추가하면 더 강력해질 수 있어. 기본 아이디어가 워낙 단순해서 적용 범위가 넓어.

📝 한 줄 요약

  • AI의 시각적 추론을 위해 기능적 토큰(Functional Token)이라는 새로운 패러다임 제안
  • ⟨|Manip|⟩ ⟨|Shape|⟩ ⟨|Line|⟩ ⟨|Arrow|⟩ ⟨|Text|⟩ 단 5개의 특수 단어만 추가하면 시각 연산이 내부적으로 수행됨
  • 기존 VLM 아키텍처 변경 없이, 표준 next-token prediction으로 작동
  • LA-GRPO로 기능적 토큰의 희소성 문제(기울기 희석) 해결
  • 시각 추론·기하학·공간 추론 벤치마크 전체 1위, 추론 오버헤드는 최소
  • 에이전트(도구 호출)와 잠재 방식(숨겨진 표현)의 장점만 결합한 제3의 패러다임
